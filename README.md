## 1. 프로젝트 개요

- 프로젝트명: Smart Rainwater Monitoring System(SRMS)
- 프로젝트 목적: 기상청 Open API로 수집한 기상 데이터를 공통 SensorData 형식으로 표준화한 후, 빗물 재활용 시설(Rainwater Recycling Facility)의 디지털 트윈(3D) 환경에서 설비 상태를 시각적으로 모니터링
- 구현 범위:
  - 기상청 Open API 연동
  - WeatherData → SensorData 표준화
  - 설비 상태(Status) 계산
  - React Three Fiber 기반 3D 디지털 트윈
  - 설비 선택(Click)
  - 설비 상태 카드
  - 상태별 색상 시각화
  - API 예외 처리
  - AX 이상징후 분석 카드
  - 시연용 더미 데이터 모드
- 주요 기능:
  - 기상청 Open API를 통한 기상 데이터 조회
  - SensorData 표준화
  - 설비 상태 자동 계산
  - 3D 설비 모델 표시
  - 설비 선택 및 상태 조회
  - Hover Outline 효과
  - 상태별 색상 표시(정상·주의·위험)
  - 이상 원인, 판단 근거, 권장 조치 자동 출력
  - 시연 모드에서 이상 상황 재현

## 7. Open API 연동 설명

- API 제공 기관: 기상청
- API 이름: 단기예보 조회서비스
- API 데이터 출처(URL): https://www.data.go.kr/
- 호출 방법(엔드포인트/HTTP 메서드): GET https://apis.data.go.kr/1360000/VilageFcstInfoService_2.0/getVilageFcst
- 사용한 주요 요청값: serviceKey, base_date, base_time, nx, ny, dataType

- 응답 데이터 구조:

```json
{
    "response": {
        "header": {

            "resultMsg": "NORMAL_SERVICE"

        "body": {
            "items": {
                "item": [
                    {
                        "category": "TMP",
```

- 오류 처리 방법:

  - 오류 발생 시 사용자에게 오류 메시지 출력

## 8. 데이터 표준화 방법

- 기상청 Open API 응답을 WeatherData 객체로 가공한 후 SensorData 구조로 표준화
- 표준 데이터 구조:

```ts
interface SensorData {
  timestamp: string;
  sensorId: string;
  sensorName: string;
  sensorType: string;
  value: number;
  unit: string;
  location: string;
  status: "normal" | "warning" | "danger";
  isAnomaly: boolean;
  source: string;
}
```

- 컬럼 변환 방법:
  - `WeatherData`를 `sensorMapper`를 통해 `SensorData[]`로 변환
  - 센서 ID, 이름, 타입, 단위는 메타데이터로 관리하여 공통 SensorData 구조를 생성
- 결측값 처리: 강수량이 `"강수없음"`인 경우 `0(mm)`으로 변환
- 중복값 처리: 동일 예보 시각(fcstTime)의 데이터만 선택하여 변환하므로 중복 데이터가 생성되지 않음
- 시간 형식 처리: 센서 데이터 생성 시 `Date.toISOString()`을 사용하여 ISO 8601 형식으로 저장

## 9. 3D 구현 설명

- 사용한 3D 기술:
  - React Three Fiber
  - Three.js
- 설비 구성(최소 4종):
  - 저장탱크(Storage Tank)
  - 펌프(Pump)
  - 필터(Filter)
  - 재사용탱크(Reuse Tank)
- 객체 선택 방법:
  - React Three Fiber의 Pointer Event를 이용하여 설비 선택 기능을 구현
  - Hover 시 Outline 효과를 적용하여 선택 가능한 설비를 시각적으로 강조
  - 빈 공간 클릭 시 선택 상태 해제
- 센서와 3D 객체 연결 방법:
  - 기상청 Open API 데이터를 `WeatherData`로 변환한 후 `SensorData`로 표준화
  - `statusService`에서 설비별 센서값(수위, 유량, 필터 부하, 수질)을 생성하고 상태를 계산
  - 계산된 상태 정보를 각 3D 설비 모델과 설비 상태 카드에 전달하여 동일한 상태를 표시
- 상태별 시각화 방법(정상·주의·위험):
  - 정상: 회색으로 표시
  - 주의: 노란색으로 표시
  - 위험: 빨간색으로 표시
  - 설비 상태에 따라 3D 모델의 색상과 설비 상태 카드의 상태 표시를 함께 변경하도록 구현

## 10. 이상징후 판단 방법

- 이상 탐지 로직 소스코드:
  - 설비 상태 판정: `src/services/statusService.ts`
  - 이상징후 분석 문장 생성: `src/services/analysisService.ts`
  - 시연용 이상 상황 데이터: `src/data/demoWeather.ts`
- 사용한 알고리즘: 임계값(Threshold) 기반 규칙 엔진
  - 기상청 Open API에서 조회한 기온, 습도, 강수확률, 강수량을 SensorData로 표준화
  - 표준화된 센서 데이터를 기반으로 설비별 가상 운영 지표를 계산
  - 각 지표가 사전에 정의한 임계값을 초과하거나 미달하면 정상·주의·위험으로 상태를 분류
  - 위험 또는 주의 상태가 발생하면 AX 이상징후 분석 카드에 원인, 판단 근거, 권장 조치를 자동 생성

### 10-1. 설비별 운영 지표 계산식

실제 설비 센서 데이터가 제공되지 않았기 때문에, 공개 기상 데이터를 설비 부하에 영향을 주는 외부 환경 변수로 보고 아래 계산식을 적용했다.

| 설비 | 계산 지표 | 계산식 |
| --- | --- | --- |
| 저장탱크 | 수위(%) | `min(100, 습도 * 0.3 + 강수확률 * 0.7 + 강수량 * 10)` |
| 펌프 | 유량(L/min) | `min(40, 강수확률 * 0.25 + 강수량 * 5)` |
| 필터 | 필터 부하(%) | `min(100, 습도 * 0.2 + 강수확률 * 0.6 + 강수량 * 8)` |
| 재사용탱크 | 수질(%) | `max(0, 100 - 강수확률 * 0.35 - 강수량 * 5 + 기온 * 0.3)` |

### 10-2. 임계 기준

| 설비 | 정상 | 주의 | 위험 |
| --- | --- | --- | --- |
| 저장탱크 수위 | 70% 미만 | 70% 이상 90% 미만 | 90% 이상 |
| 펌프 유량 | 20 L/min 미만 | 20 L/min 이상 35 L/min 미만 | 35 L/min 이상 |
| 필터 부하 | 70% 미만 | 70% 이상 90% 미만 | 90% 이상 |
| 재사용탱크 수질 | 70% 초과 | 50% 초과 70% 이하 | 50% 이하 |

### 10-3. AX 분석 카드 판단 기준

| 이상징후 | 레벨 | 조건 | 출력 내용 |
| --- | --- | --- | --- |
| 저장탱크 과충전 위험 | 위험 | 저장탱크 수위 90% 이상 | 현재 수위, 안전 기준, 저장 용량 확보 권장 |
| 펌프 과부하 | 위험 | 펌프 유량 35 L/min 이상 | 현재 유량, 위험 기준, 펌프 점검 및 유입량 조절 권장 |
| 펌프 유량 증가 | 주의 | 펌프 유량 20 L/min 이상 | 현재 유량, 주의 기준, 운전 상태 및 배출 경로 확인 권장 |
| 필터 막힘 | 위험 | 필터 부하 90% 이상 | 필터 부하, 위험 기준, 필터 점검 또는 교체 권장 |
| 재사용수 수질 저하 | 위험 | 수질 50% 이하 | 현재 수질, 정상 기준, 수질 점검 권장 |
| 강우량 증가 예상 | 주의 | 강수확률 80% 이상이고 강수량 5mm 이상 | 강수확률, 강수량, 저장탱크 용량 확보 권장 |
| 범람 위험 | 위험 | 저장탱크 수위 80% 이상이고 강수확률 80% 이상 | 저장탱크 수위, 강수확률, 유입량 조절 권장 |
| 고온 환경 | 주의 | 기온 35℃ 이상 | 현재 기온, 설비 효율 저하 가능성 안내 |
| 고습 환경 | 주의 | 습도 90% 이상 | 현재 습도, 필터 상태 확인 권장 |

### 10-4. 기준 선택 이유

- 빗물 재활용 시설은 강수량, 강수확률, 습도 증가에 따라 저장탱크 수위와 필터 부하가 커질 가능성이 높다.
- 저장탱크 수위와 필터 부하는 70% 이상을 주의, 90% 이상을 위험으로 설정해 운영자가 사전에 점검할 수 있도록 했다.
- 펌프 유량은 강수 상황에서 급격히 증가할 수 있으므로 20 L/min 이상을 주의, 35 L/min 이상을 위험으로 설정했다.
- 재사용탱크 수질은 수치가 낮을수록 위험하므로 다른 설비와 반대로 70% 이하를 주의, 50% 이하를 위험으로 설정했다.
- 본 프로젝트는 프로토타입이므로 실제 산업 현장의 법정 기준이 아니라 시연과 상태 분류가 가능한 합리적 임계값을 적용했다.

### 10-5. 한계점

- 실제 설비 센서가 아닌 기상청 Open API 데이터를 기반으로 설비 상태를 추정한다.
- 임계값은 현장 실측 데이터로 검증된 값이 아니라 프로토타입 시연을 위한 규칙 기반 기준이다.
- 장비별 고장 이력, 시간대별 추세, 머신러닝 기반 예측은 적용하지 않았다.
- 향후 실제 수위계, 유량계, 수질 센서 데이터를 연동하면 임계값 보정과 예측 모델 적용이 가능하다.

### 12-1. 이상 상황 재현 시나리오

시연용 더미 데이터 모드를 사용하면 실제 API 상태와 관계없이 이상 상황을 재현할 수 있다.

1. 개발 서버 실행

```bash
npm run dev
```

2. 브라우저 접속

```text
http://localhost:5173/?demo=bad
```

3. 또는 화면 우측 상단의 `실시간 데이터 / 시연 데이터` 토글을 `시연 데이터`로 전환

4. 시연용 입력 데이터

| 항목 | 값 |
| --- | --- |
| 기온 | 36℃ |
| 습도 | 80% |
| 강수확률 | 75% |
| 강수량 | 2mm |

5. 예상 결과

| 설비 | 예상 상태 | 근거 |
| --- | --- | --- |
| 저장탱크 | 위험 | 계산 수위가 90% 이상 |
| 펌프 | 주의 | 계산 유량이 20 L/min 이상 35 L/min 미만 |
| 필터 | 주의 | 계산 필터 부하가 70% 이상 90% 미만 |
| 재사용탱크 | 정상 | 계산 수질이 70% 초과 |

## 13. 미구현 사항 및 한계

- 구현하지 못한 기능:
  - 설비별 이상 이력 저장 기능
  - 이상 알람 확인 처리 및 알림 전송 기능
  - 머신러닝 기반 이상 탐지 기능
- 발생한 문제: 실제 설비 센서 데이터가 제공되지 않아 기상청 Open API 데이터를 기반으로 설비 상태를 생성하는 방식으로 구현
- 해결하지 못한 이유: 과제 요구사항에 실제 설비 데이터 연동 환경이 제공되지 않아 기상 데이터를 활용한 시뮬레이션 방식으로 구현
- 추가 개발 방향:
  - 실제 수위계, 유량계, 필터 차압계, 수질 센서 데이터 연동
  - 이상 이력 저장 및 통계 기능 추가
  - 운영자 알림 기능 추가
  - 운영 지원 기능 추가
